# Explain visually

Prose is what already failed, so more of it is the one move ruled out. Render
instead, and let the gap pick the form. A structure — a flow, a state change,
how parts relate — is a picture. A mechanism is real values run through it, step
by visible step. A why-this-and-not-that is the alternatives side by side. This
is not a fixed vocabulary of shapes: a table, a timeline, annotated code, a
before-and-after all count when they are what shows the thing. Render with
whatever the environment offers, cheapest first.

Do not ask the user what exactly is unclear. Guess the gap — the level, the
mechanism, why not the alternative — and render that. A wrong guess gets
corrected, and the correction narrows it faster than a question would. A gap one
sentence closes, a single unfamiliar word, is not this skill's work: say the
sentence and stop.

Work from the real code, docs, or sources. Rendering what you already believe
sets a wrong model in concrete, and a picture is harder to doubt than a
sentence — the confidence the form carries is what makes a wrong one expensive.
Keep one level per view, because mixing levels is what made the thing hard in
the first place. Use no analogy you cannot defend when the user pushes on it.
