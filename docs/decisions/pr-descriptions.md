# PR 본문

## Decisions

- PR 본문 자체가 변경 전후, 변경 이유, 검증 근거를 이해할 수 있는 설명을
  제공한다. 주요 선택과 감수한 단점, 핵심 동작 원리, 영향 범위, 검토할
  가정은 해당 변경을 판단하는 데 필요할 때 포함한다.
- 설명의 깊이는 변경의 규모와 성격에 맞춘다. 모든 PR에 동일한 항목을
  채우거나 존재하지 않는 대안과 질문을 만들어 넣지 않는다.
- 화면 변경은 실제 변경 전후 화면을 가능한 한 같은 화면 크기, 데이터,
  상태로 촬영하여 PR 본문에서 나란히 비교할 수 있게 한다. 비교 아래에
  달라진 점과 이유를 적는다. 상호작용이 판단의 핵심이면 영상도 활용한다.
- 이미지는 GitHub 첨부로 업로드해 본문 안에 표시한다. 리뷰용 이미지의
  저장소 커밋이나 별도 이미지 호스팅을 기본 전제로 삼지 않는다.
- 첨부 전에 이미지와 영상의 자격 증명, 개인정보, 비공개 정보를 확인한다.
  안전한 테스트 데이터로 촬영하거나 해당 정보를 가린 뒤 검사한 자료만
  업로드하며, 전후 비교 조건과 판단할 변화는 유지한다.
- 실제로 관찰한 결과, 소스에서 추론한 동작, 미확인 사항을 구분한다.
  변경 전 화면이나 첨부를 확보하지 못하면 그 한계를 밝히고 확보한 증거만
  제공한다. 의도한 화면이나 프로토타입을 실제 실행 결과로 제시하지 않는다.
- 본문은 전체 변경의 의미를 설명하면서 중요한 판단 지점을 강조한다.
  AI가 선정한 질문만으로 사람의 검토 범위를 제한하지 않는다.
- 저장소의 agent 지침에 `## Issue tracker` 섹션이 있고 브랜치 커밋에
  `Spec-Folder: docs/specs/<slug>/` 트레일러가 있으면, `pr`와 `merge`는 그
  폴더의 이슈를 섹션의 키로 찾아 섹션이 정한 닫기 참조를 본문에 넣는다.
  섹션이 없으면 본문은 그대로다.

## Boundaries

- 이 결정은 GitHub PR 본문에 관한 것이다. 별도의 리뷰 문서나 인터랙티브
  리뷰 화면을 필수로 만들거나 새로운 승인 단계를 추가하지 않는다.
- 본문 설명과 첨부의 존재는 사람의 승인이나 기능 검증 완료를 뜻하지 않는다.
- PR 생성·수정 권한과 병합 권한은 기존 Git 전달 스킬의 경계를 따른다.

## Why

파일과 구현 작업의 나열만으로는 사용자가 무엇을 경험하게 되는지, 어떤
선택과 비용을 승인하는지 알기 어렵다. 구체적인 변경 전후와 실제 증거는
이해를 돕고, 변화에 맞춘 설명은 작은 수정에 불필요한 형식을 더하지 않는다.
화면 비교를 본문에 직접 넣으면 리뷰어가 별도 도구에서 결과를 재구성할
필요가 줄어든다.

## Reconsider when

- 본문이 반복적으로 길어져 중요한 변화나 미확인 사항을 찾기 어려워진다.
- GitHub 첨부의 지원이나 접근 조건이 바뀌어 리뷰어가 결과를 볼 수 없다.
- 촬영 조건을 맞추기 어려운 변경에서 전후 비교가 실제 차이를 오해하게 한다.

## Still-rejected alternatives

- 모든 PR에 동일한 여섯 항목을 강제하는 양식 — 작은 변경의 설명 비용이
  커지고 의미 없는 대안과 질문을 만들게 된다.
- 로컬 파일 경로나 프리뷰 링크만으로 화면 비교를 대체 — PR 본문에서 바로
  결과를 보고 판단하려는 요구를 충족하지 못한다. 확보 실패 시에는 한계와
  함께 사용 가능한 보조 증거로 제시할 수 있다.

## Evidence worth preserving

- 2026-09-16 설치된 GitHub CLI 2.100.0의 `gh pr create --help`에서
  `--attach`, 본문 이미지 경로의 업로드 URL 치환, 부분 업로드 실패 동작을
  확인했다. 실제 원격 업로드는 이 shaping 세션에서 수행하지 않았다.
- [GitHub 공식 첨부 문서](https://docs.github.com/en/github-cli/github-cli/attaching-files-with-github-cli)는
  생성·수정 시 이미지와 영상 첨부, 본문의 로컬 참조 치환, 저장소 push 권한
  요건을 설명한다. 실행 시점의 도구와 권한에 따라 지원 여부를 확인한다.
- 격리된 Codex CLI 행동 평가에서 기존 지침은 전후 이미지를 세로로 배치하고
  불필요한 대안 부재 설명을 넣었다. 수정된 지침은 나란한 비교, 간단한 오타
  수정의 짧은 설명, 실제 결제 제공자 미검증 표시, 기준 화면 실행 실패와 모형
  구분, 최신 이미지·영상으로 기존 PR 갱신을 보여줬다.
- 부분 업로드 실패 사례에서는 `merge`가 본문을 교체하며 성공한 첨부의 참조를
  빠뜨렸다. 원격 본문의 성공한 첨부 URL을 교체 본문에 옮기도록 구체화한 뒤,
  다른 화면과 502 오류를 사용한 새 사례에서 두 스킬 모두 정확한 기존 URL을
  보존하고 실패한 로컬 이미지 참조를 한계 설명으로 바꿨다.
- 이 평가는 `gpt-5.6-sol`에 스킬과 통제된 상황을 제공해 생성한 본문·명령을
  검사한 것이다. 실제 캡처 도구 실행, GitHub 업로드·렌더링, 원격 병합·정리의
  통합 검증은 아니다. 재실행용 상황과 기대 결과는 각 스킬의 evals에 보존한다.
