# 변경을 이해하고 판단할 수 있는 PR 본문

## 문제

현재 PR 작성 지침은 실제 변경을 설명하는 제목·요약·검증 근거를 요구하지만,
리뷰어가 변경 전후의 동작과 중요한 선택을 이해할 수 있는 설명, 화면 변경의
직관적인 전후 비교까지 보장하지 않는다. 이 작업은 GitHub PR 본문만 읽어도
무엇이 바뀌고 왜 그렇게 바뀌었으며 무엇을 판단해야 하는지 알 수 있게 한다.

## 필수 참고 결정

- [PR 본문](../../decisions/pr-descriptions.md): 설명의 깊이, 시각적 증거,
  첨부와 검증 한계, 리뷰어 판단 범위를 규정한다.
- [스킬 설계](../../decisions/skill-design.md): 결과 중심 지침과 각 스킬의
  독립 실행 원칙을 규정한다.
- [문서 수명주기](../../decisions/document-lifecycles.md): 이 스펙의 유지와
  작업 완료 후 정리 기준을 규정한다.

## 사용자에게 보이는 결과

- 리뷰어는 대화 이력 없이 PR 본문에서 문제, 변경 전후의 결과, 이유와
  검증 근거를 이해한다.
- 주요 선택의 이유와 비용, 동작 원리, 영향, 남은 불확실성은 그 변경을
  판단하는 데 필요한 만큼 드러난다.
- 화면이 바뀌는 PR은 본문에서 실제 전후 스크린샷을 직접 비교할 수 있다.
  상호작용의 차이는 필요한 경우 첨부 영상으로 확인할 수 있다.
- 증거를 확보하지 못한 경우에도 무엇을 확인했고 무엇을 확인하지 못했는지
  알 수 있다.

## 승인된 범위

- PR 생성 및 기존 PR 본문 갱신 시 변경의 의미와 근거를 전달하는 방식.
- 화면 변경의 실제 전후 촬영, GitHub 첨부, 본문 내 비교와 짧은 설명.
- 변경 성격에 맞춘 설명 길이와 매체 선택. 단순 수정은 짧은 설명으로 끝낸다.
- 실제 결과에 근거한 검증 상태와 중요한 미확인 사항의 표시.
- 설치된 플러그인과 개별 설치 스킬에서 같은 결과를 얻는 것.

## 수용 기준

1. 동작 변경 PR 본문을 읽으면 구체적인 상황에서 기존 결과와 새 결과를
   설명할 수 있다. 파일 목록이나 수행한 작업의 나열만으로 끝나지 않는다.
2. 중요한 선택이 있는 변경은 선택 이유와 감수한 단점을 설명한다. 실제로
   고려한 대안만 소개하고, 단순 수정에는 대안·질문·빈 항목을 만들지 않는다.
3. 여러 단계나 분기가 이해에 필요한 변경은 핵심 동작을 설명하며, 필요하면
   본문에서 읽을 수 있는 다이어그램을 활용한다.
4. 변경 전후 화면을 실행할 수 있는 UI 변경은 같은 화면 크기·데이터·상태로
   촬영한 이미지를 본문에서 나란히 보여주고 차이와 이유를 설명한다.
   불가피한 촬영 조건 차이는 표시한다.
5. 첨부 이미지는 GitHub에 업로드되어 PR 독자가 본문에서 볼 수 있다.
   작성자의 로컬 경로만 남아 있거나 파일 업로드 없이 성공을 주장하지 않는다.
6. 스크린샷이 중요한 상호작용을 설명하기 어려운 경우 영상 등 적절한 실제
   증거를 추가한다. 정적인 화면 변경에 영상을 일괄 요구하지 않는다.
7. 변경 전 실행 불가, 촬영 실패, 첨부 지원 또는 권한 부족이 있으면 구체적인
   한계와 확보한 증거를 적는다. 프로토타입이나 추정 이미지를 실제 결과로
   대신하지 않는다. 부분 업로드 실패도 전체 성공으로 보고하지 않는다.
8. 검증 근거는 무엇을 확인했는지 설명하며, 중요한 미확인 상태는 본문에서
   찾을 수 있다. 테스트 명령의 성공만으로 화면 검증을 했다고 주장하지 않는다.
9. 이미 존재하는 PR을 갱신할 때 본문과 시각적 증거는 최종 변경과 일치한다.
   결과에 영향을 준 후속 변경이 있으면 오래된 증거를 현재 결과로 제시하지 않는다.
10. 중요한 가정이나 미해결 선택이 있으면 구체적으로 드러내되, 질문이 없는
    변경에는 판단 질문을 만들지 않는다. 전체 변경의 의미도 계속 이해할 수 있다.

## 확정된 제약과 이유

본문의 설명·증거·예외 기준은 연결된 PR 본문 결정을 따른다. 고정 템플릿보다
변경의 의미와 판단 가능성을 우선한다. 첨부의 수단은 실행 환경의 실제 지원을
따르며, 특정 CLI 버전을 모든 설치 환경에 존재한다고 가정하지 않는다.

## 가정

- 기본 적용 범위는 직접 PR을 만드는 흐름뿐 아니라 병합 요청 중 PR을
  생성하거나 갱신하는 흐름도 포함한다. 같은 PR 결과에 같은 기준이 필요하다는
  에이전트의 기본 판단이며, 사용자가 범위를 좁힐 수 있다.
- 기존에 확보한 촬영 결과가 해당 변경과 비교 조건을 충족하면 재사용할 수 있다.
  불필요한 재촬영을 피하기 위한 기본값이다.

## 범위 밖

- 별도 리뷰 앱, 슬라이더, HTML 리뷰 페이지 개발: 결과를 보는 기본 장소는
  GitHub PR 본문이다.
- 새로운 이미지 호스팅 서비스나 리뷰용 스크린샷의 저장소 보관 체계 구축:
  GitHub 첨부로 충족할 수 있는 요구다.
- 사람의 승인 절차, 브랜치 보호, 자동 리뷰 또는 병합 권한 변경:
  본문을 개선하는 작업이 그 정책까지 바꾸지는 않는다.
- 화면 변경이 없는 PR의 의무 촬영 및 모든 화면·기기 조합의 전수 촬영:
  변경 이해에 필요한 증거를 확보하는 범위다.

## 보류된 결정

없음. 환경에 따라 증거를 확보하지 못할 때의 동작은 수용 기준에 포함한다.

## 남은 위험과 검증 한계

- 데이터와 외부 서비스의 변동으로 비교 조건을 완전히 맞추지 못할 수 있다.
- 첨부의 실제 표시와 접근 가능 여부는 게시된 PR에서 확인해야 한다.
  이번 shaping에서는 공식 문서와 설치 CLI의 기능까지만 확인했다.
- 본문의 가독성과 판단 가능성은 항목 존재 여부만으로 입증되지 않는다.
  단순 수정, 동작 변경, 화면 변경, 증거 확보 실패 사례에서 결과를 확인해야 한다.
