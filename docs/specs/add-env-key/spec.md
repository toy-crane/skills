# 발급받아야 하는 키를 `.env`에 넣기 (`add-env-key` 스킬)

- 결정: [skill-design](../../decisions/skill-design.md). 스킬이 mod를 필수로 요구하지 않고, 있으면 쓰고 없으면 같은 결과를 스스로 낸다는 규칙을 정한다.
- 결정: [mod-layout](../../decisions/mod-layout.md). `secret-env` mod가 플러그인으로만 설치된다는 점을 정한다.
- 결정: [skill-naming](../../decisions/skill-naming.md), [skill-layout](../../decisions/skill-layout.md). 이름 형식과 그룹을 정한다.
- 관련 스펙: [secret-env](../secret-env/spec.md). mod 쪽 입력 패널, 가리기, `.gitignore` 경고, 덮어쓰기 확인의 동작은 그 스펙이 정한다.

## 문제

작업 중에 API 키나 토큰처럼 사용자가 외부 서비스에서 발급받아야 하는 값이 필요해진다. 지금은 사용자가 발급 페이지를 직접 찾고, 어느 파일에 어떤 이름으로 넣을지도 직접 알아내야 한다. 값을 채팅에 붙여 넣으면 모델 컨텍스트와 대화 기록에 남는다.

## 사용자에게 보이는 결과

- Claude가 발급받아야 하는 키가 필요하다고 판단하거나 사용자가 키를 넣어 달라고 하면, 그 키의 발급 페이지가 사용자의 브라우저에서 열린다. 채팅에도 같은 URL이 나온다.
- `secret-env` mod가 켜진 세션에서는 채팅 옆에 키 입력 패널이 열린다. 키 이름, 용도, 저장할 파일은 Claude가 채워 둔다. 사용자는 값만 붙여 넣으면 되고, 값은 Claude에게 보이지 않는다.
- mod가 없는 세션에서는 저장할 `.env` 계열 파일이 사용자의 편집기에서 열린다. 파일에는 `키이름=` 줄이 이미 들어 있어서 값만 붙여 넣으면 된다. 이 경로에서는 값이 가려지지 않는다는 점과, `secret-env@toycrane`을 설치하면 가려진다는 점을 한 번 안내받는다.
- 입력을 마치면 Claude가 값을 출력하지 않고 키가 들어갔는지만 확인한 뒤 하던 일을 이어 간다.

## 승인된 범위

- `skills/workflow/add-env-key/`에 두는 새 공개 스킬. `plugin.json`, 두 심볼릭 링크, README 등록을 함께 한다.
- 키 이름, 용도, 저장할 파일, 발급 페이지를 프로젝트와 서비스에 맞게 정하는 일.
- mod가 있을 때 mod의 키 입력 도구로 값을 받는 경로.
- mod가 없을 때 파일에 빈 키 줄을 넣고 편집기로 여는 경로.
- 두 경로 모두에서 발급 페이지를 열고, 값을 보지 않고 입력 완료를 확인하는 일.

## 수용 기준

1. mod가 있는 세션에서 키가 필요하면, Claude는 mod의 키 입력 도구를 키 이름, 용도, 저장 파일과 함께 호출하고 발급 페이지를 연다. 채팅으로 값을 달라고 하지 않는다.
2. mod가 없는 세션에서 키가 필요하면, 대상 파일에 `키이름=` 줄이 생기고(이미 있으면 그 줄을 그대로 둔다) 그 파일이 편집기에서 열리며 발급 페이지도 열린다. 다른 줄은 순서와 내용이 그대로다.
3. mod가 없는 경로에서 대상 파일이 Git 저장소 안에 있는데 `.gitignore`에 걸리지 않으면, 파일을 열기 전에 경고하고 `.gitignore`에 추가하는 선택지를 준다.
4. mod가 없는 경로에서 사용자가 입력을 마쳤다고 하면, Claude는 그 키 줄에 값이 비어 있지 않은지만 확인한다. 확인 결과에도 채팅에도 값이 나타나지 않는다. 비어 있으면 다시 넣어 달라고 알린다.
5. 사용자가 mod 패널에서 취소하면 아무 파일도 바뀌지 않고, Claude는 키 없이 진행할 수 있는지 사용자에게 묻는다.
6. 스킬의 행동은 eval로 확인한다. `skill-evals/add-env-key/`에 두고, 서비스별 키가 필요한 상황 프롬프트를 개발용과 보류용으로 나눈다. 보류용은 개발용과 겹치지 않는 서비스로 최소 10건을 mod가 있는 조건과 없는 조건에 각각 돌린다.
   - 지표: 각 조건에서 기준 1 또는 기준 2·4의 행동을 모두 지킨 건수의 비율.
   - 목표: 조건마다 보류용 9/10 이상. 값을 채팅으로 요청하거나 출력한 건은 0건.
7. 저장소 전체가 `claude plugin validate . --strict`를 통과한다.

## 확정된 제약과 이유

- mod를 우선 쓰고, 없을 때만 편집기를 연다. mod는 값을 모든 도구 결과에서 가리고, 저장과 취소가 끝나면 결과가 바로 돌아오며, `.gitignore`와 덮어쓰기 확인을 이미 한다. 편집기만 쓰면 이 셋을 모두 잃는다.
- mod를 필수로 요구하지 않는다. mod는 플러그인으로만 설치되어 skills.sh 사용자에게 설치 명령을 줄 수 없다([skill-design](../../decisions/skill-design.md), [mod-layout](../../decisions/mod-layout.md)).
- 이 스킬은 독립 스킬로만 만든다. `implement`가 셋팅 항목에서 멈추고 보고하는 규칙([pipeline](../../decisions/pipeline.md))은 바꾸지 않는다. 연결은 아래 보류한 점에 둔다.

## 가정 (수정 가능)

- 이름은 `add-env-key`, 그룹은 `workflow`다. 사용자가 직접 부르는 스킬이라 동사-목적어 형식을 따랐다.
- 대상은 사용자가 외부에서 발급받거나 직접 알려 줘야 하는 값(API 키, 토큰, 비밀번호)이다. `PORT=3000`처럼 Claude가 정할 수 있는 값은 Claude가 그냥 쓴다.
- 저장 파일은 프로젝트 관례를 보고 정한다(`.env.local`, `.env` 등). 관례가 없으면 프로젝트 루트의 `.env`다.
- 발급 페이지는 서비스 공식 문서를 근거로 정한다. 키 발급 화면으로 바로 가는 주소가 없으면 발급 방법을 설명하는 문서 페이지를 연다.
- 키가 여러 개 필요하면 하나씩 차례로 받는다.
- 편집기는 사용자의 기본 텍스트 편집기나 프로젝트에서 쓰는 편집기 CLI로 연다. 열지 못하면 파일 경로와 넣을 줄을 채팅으로 알린다.

## 범위 밖

- `implement`의 셋팅 단계 연결. 사용자가 이번에는 독립 스킬로만 만들기로 했다.
- `secret-env` mod 자체의 변경. 발급 페이지 열기도 스킬이 맡는다.
- MCP 서버 설정에 토큰을 넣는 일. `secret-env` 스펙과 같은 이유로 다른 경로가 필요하다.
- 사용자를 대신해 발급 페이지에서 키를 만드는 일. 계정 안에서 키를 만드는 결정은 사용자의 몫이다.

## 보류한 점

- `implement`에서 이 스킬을 불러 키 셋팅 항목을 그 자리에서 처리할지. 그동안 `implement`는 지금처럼 남은 셋팅을 보고하고 멈춘다.
  - 다시 꺼낼 때: 이 스킬이 `main`에 들어간 뒤, `implement`가 발급 키 셋팅 항목 때문에 멈추는 일이 처음 생길 때.

## 남은 위험

- mod가 없는 경로에서는 값이 가려지지 않는다. 나중에 Claude가 그 파일을 읽으면 값이 모델 컨텍스트에 들어간다.
- Remote Control로 휴대폰에서 따라오는 사용자에게는 로컬 편집기와 브라우저가 열려도 보이지 않는다. mod가 없으면 사실상 컴퓨터 앞에서 해야 한다.
- 서비스가 콘솔 주소를 바꾸면 발급 페이지 주소가 틀릴 수 있다.
- mod 패널 입력값이 대화 기록 파일에 남는지는 `secret-env` 스펙의 남은 위험을 그대로 물려받는다.
