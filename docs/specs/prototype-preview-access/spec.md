# Prototype 미리보기 접근 범위 확인

관련 결정: [build-prototype](../../decisions/build-prototype.md)은 미리보기
접근 질문의 조건과 기존 prototype 완료 기준을 정의한다.
[skill-design](../../decisions/skill-design.md)은 목표 중심 지침과 상황에 따른
방법 선택을 정의한다.

## 사용자에게 보이는 결과

미리보기를 어디에서 열어볼지 불분명할 때만, 작업을 실행하는 컴퓨터에서만
확인할지 다른 기기에서도 확인할지 한 번 묻는다. 비동기 질문 수단이 있으면
답변을 기다리는 동안 제작하고, 없으면 접근 방식과 무관한 제작을 먼저 마친다.
확인된 접근 범위에 맞게 실행 가능한 주소를 제공한다.

## 승인된 범위

- 전체 prototype과 임시 비교 화면을 전달하기 위한 접근 범위 확인.
- 특정 서비스나 하네스에 종속되지 않는 실행 방식 선택.

## 수용 기준

- 접근 범위가 불분명하면 같은 컴퓨터에서만 볼지 다른 기기에서도 볼지 묻는다.
- 이미 접근 범위가 알려져 있으면 같은 질문을 반복하지 않는다.
- 비동기 질문 수단이 있으면 답변 대기가 제작을 막지 않는다.
- 질문이 작업을 중단시키는 환경에서는 접근 방식과 무관한 제작을 먼저 마친다.
- 다른 기기에서도 확인하려는 사용자에게 localhost만 제공하고 완료하지 않는다.
- 실행 OS나 Desktop 도구의 존재만으로 사용자의 열람 기기를 확정하지 않는다.
- 사용자가 열어 조작할 수 있는 결과를 제공하며 기존 브라우저 검증 기준을 유지한다.
- 호스팅 업체나 저장소 지침을 읽는 순서를 추가로 고정하지 않는다.

## 확정된 제약과 이유

사용자가 정하는 것은 접근 범위이고, 실행 방법은 에이전트가 환경에 맞게
선택한다. 실행 컴퓨터와 열람 기기가 다를 수 있어 기기 추측은 충분하지 않다.
기본적인 사용자 요청 및 저장소 지침 준수를 별도 절차로 반복하지 않는다.

## 가정

접근 범위를 알아야 하는 시점 전에 비동기로 질문하거나, 동기식 환경에서는
접근 방식과 무관한 제작을 먼저 마칠 수 있다. 답변이 없다는 사실을 특정 접근
방식에 대한 동의로 간주하지 않는다.

## 범위 밖

- 특정 호스팅 서비스 설치, 계정 연결, 다른 저장소 설정: 이 스킬의 공통 계약이 아니다.
- prototype 화면 구성과 보존 정책: 기존 결정을 유지한다.
- 사용자 접속 기기를 판별하는 별도 기능: 접근 범위 질문으로 해결한다.

## 유보 사항

없음. 개별 환경의 서비스 선택은 실행 시 판단한다.

## 남은 위험

외부 접근 방식은 해당 환경의 인증이나 호스팅 도구 부재로 실행되지 못할 수 있다.
이 경우 접근 가능한 미리보기를 제공했다는 완료 주장을 할 수 없다.
