# Claude가 모르는 비밀 키 입력 (`secret-env` mod)

- 프로토타입: [prototype.html](prototype.html). 입력 패널과 키 목록의 화면 구성, 문구, 상태(대기, 저장 완료, 취소, `.gitignore` 경고, 덮어쓰기 확인, 키 없음)를 정한다.
- 결정: [mod-layout](../../decisions/mod-layout.md). mod를 두는 위치, marketplace 등록, 배포 경로를 정한다.

## 문제

Claude Code로 작업하다 보면 API 키 같은 비밀 값이 필요한 순간이 온다. 지금은 사용자가 채팅에 키를 붙여 넣거나 직접 `.env`를 편집해야 한다. 채팅에 붙여 넣으면 값이 모델 컨텍스트와 대화 기록에 남는다. `.env`를 직접 편집해도 Claude가 그 파일을 읽거나 출력하면 결국 값이 모델에게 보인다.

## 사용자에게 보이는 결과

- Claude가 키가 필요하다고 판단하면, 채팅 옆에 키 입력 패널이 열린다. 패널에는 키 이름, 용도, 저장할 파일이 보이고, Claude는 입력이 끝날 때까지 기다린다.
- 사용자가 `/secret-env` 명령으로 패널을 열어 키를 미리 등록하거나, 관리 중인 키 목록을 보고 지울 수도 있다.
- 사용자가 입력한 값은 프로젝트의 `.env` 계열 파일에 저장된다. 앱과 스크립트는 평소처럼 그 파일에서 키를 읽는다. Claude가 띄운 프로세스든 사용자가 직접 띄운 프로세스든 같다.
- Claude는 키 이름과 저장 결과만 받는다. Claude가 보는 모든 도구 결과에서 관리 중인 키의 값은 `[hidden]`으로 바뀐다.

## 승인된 범위

- 이 저장소의 `mods/secret-env/`에 두고, `toycrane` marketplace에 `toycrane-skills`와 별도 항목으로 등록하는 Claude Code mod. 위치와 배포 규칙은 [mod-layout](../../decisions/mod-layout.md)을 따른다.
- Claude가 호출해 키 입력을 요청하는 도구. 요청에는 키 이름, 용도, 저장할 파일이 들어간다.
- `/secret-env` 명령으로 여는 키 목록. 키 추가와 삭제를 할 수 있다.
- 입력값을 지정한 `.env` 계열 파일에 쓰는 기능.
- Claude에게 돌아가는 모든 도구 결과에서 관리 중인 키 값을 가리는 기능.

## 수용 기준

1. Claude가 키 입력을 요청하면 패널이 열리고, 키 이름, 용도, 저장 위치가 보인다. 값이 비어 있으면 저장할 수 없다.
2. 사용자가 저장하면 해당 파일에 `이름=값` 줄이 생기고, Claude는 키 이름과 파일을 알리는 결과만 받는다. 이 결과에도 대화 기록 파일에도 값이 나타나지 않는다.
3. 사용자가 취소하거나 패널을 닫으면 아무 파일도 바뀌지 않고, Claude는 사용자가 취소했다는 결과만 받는다.
4. 저장한 뒤 Claude가 Bash로 값을 출력하거나(`echo`, `env`, `cat .env`), Read나 Grep으로 파일을 열거나, 서브에이전트가 같은 일을 해도 Claude가 받는 결과에는 값 대신 `[hidden]`이 나온다. 결과의 다른 부분은 그대로다.
5. 대상 파일이 Git 저장소 안에 있는데 `.gitignore`에 걸리지 않으면, 저장 전에 경고하고 `.gitignore`에 추가한 뒤 저장하는 선택지를 준다. 그대로 저장하는 선택지는 주지 않는다.
6. 같은 파일에 같은 이름이 이미 있으면 저장 전에 덮어쓸지 확인하고, 확인하면 그 줄의 값만 바꾼다. 다른 줄은 순서와 내용을 유지한다.
7. `/secret-env` 목록에는 관리 중인 키의 이름, 파일, 저장한 시점만 보이고 값은 보이지 않는다. 키를 지우면 한 번 더 확인한 뒤 파일에서 그 줄을 지우고 목록과 가리기 대상에서도 뺀다.
8. 새 세션을 시작해도 이전에 저장한 키는 계속 가려진다. 사용자가 다시 입력할 필요가 없다.
9. mod 폴더와 저장소 전체가 `claude plugin validate --strict`를 통과하고, `/plugin install secret-env@toycrane`로 설치된다.

## 확정된 제약과 이유

- 키는 `.env` 계열 파일로 전달한다. 사용자가 원한 것은 키가 필요한 모든 곳에서 쓰이는 것이다. Claude가 실행하는 명령에만 환경 변수를 몰래 붙이는 방식은 실험으로 동작을 확인했지만, Claude 바깥에서 띄운 프로세스에는 키가 가지 않아 채택하지 않았다.
- mod API의 `$.env.set`은 소스에 적힌 고정 이름만 받는다. 임시 mod에 변수로 된 이름을 넘기자 `claude plugin validate`가 거부했다(Claude Code 2.1.304). 사용자가 정하는 이름의 키를 프로세스 환경에 넣는 길로는 쓸 수 없다.
- 도구 결과를 가리는 방식은 동작을 확인했다. `tool.call` 훅이 결과를 고쳐 돌려주자, 임시 mod로 띄운 headless 세션에서 Claude는 `val=[hidden] len=19`를 받았다. 그 세션의 대화 기록 파일에도 값이 없었다(Claude Code 2.1.304).
- mod의 입력란에는 비밀번호처럼 값을 가리는 모드가 없다. 입력하는 동안 값이 화면에 보인다. 사용자는 패널에서 이 안내를 빼기로 했다.
- `toycrane-skills` 플러그인에는 hooks 모듈을 넣지 않는다. 스킬만 원하는 사용자에게 도구 호출을 가로채는 코드가 설치되기 때문이다([mod-layout](../../decisions/mod-layout.md)).

## 가정 (수정 가능)

- `/secret-env`로 새 키를 추가할 때 저장 위치의 기본값은 프로젝트 루트의 `.env`다. Claude가 요청할 때는 Claude가 프로젝트에 맞는 파일(`.env.local` 등)을 지정한다.
- 관리 대상은 이 mod로 입력한 키뿐이다. 사용자가 직접 `.env`에 적은 키는 가리지 않는다.
- mod는 키 이름과 파일 위치만 기억하고 값은 기억하지 않는다. 가릴 값은 세션을 시작할 때와 키를 저장하거나 지울 때 파일에서 다시 읽는다.
- Claude가 Write나 Edit로 관리 중인 키의 줄을 바꾸거나 지우려 하면 거부하고 이유를 알린다. 같은 파일의 다른 줄은 Claude가 고칠 수 있다.
- 패널은 데스크톱 앱과 터미널처럼 mod pane을 그리는 화면이면 같은 흐름으로 동작한다. 실제 모양은 각 화면이 그리는 기본 요소를 따르므로 프로토타입과 색이나 상자 모양이 다를 수 있다.

## 범위 밖

- 키체인이나 외부 비밀 저장소(1Password, Vault 등)에 키를 보관하는 일. 사용자가 고른 전달 방식은 `.env` 파일이다.
- MCP 서버 설정에 토큰을 넣는 일. MCP 서버는 세션이 시작할 때 이미 떠 있어서 다른 경로가 필요하다.
- 팀원 사이의 키 공유나 동기화.
- skills.sh 배포. mod는 `SKILL.md`가 없어서 그 경로로 전달되지 않는다.

## 남은 위험

- mod가 꺼져 있거나 로드에 실패한 세션에서는 가리기가 동작하지 않는다. 그때 Claude가 `.env`를 읽으면 값이 그대로 보인다. 키는 디스크에 평문으로 남아 있기 때문이다.
- 가리기는 값이 그대로 나타날 때만 잡는다. Claude가 값을 base64로 바꾸거나 일부만 잘라 출력하면 가려지지 않는다. 또 Claude는 값을 보지 못해도 그 키를 쓰는 명령은 실행할 수 있다. 이 mod가 보장하는 것은 값이 모델 컨텍스트에 들어가지 않는다는 점이지, 키를 쓰지 못하게 막는 것은 아니다.
- 세션 중에 사용자가 mod 밖에서 `.env`의 키 값을 바꾸면, 다음에 다시 읽기 전까지 바뀐 값은 가려지지 않을 수 있다.
- 입력하는 동안 값이 화면에 보인다. 화면을 공유하거나 녹화하는 중이면 키가 노출될 수 있다.
- 실험은 Claude Code 2.1.304에서 했다. 훅 이벤트나 도구 결과 형식이 바뀌면 가리기가 깨질 수 있다. Claude Code 버전이 바뀔 때 가리기를 다시 확인할 방법이 필요하다.
