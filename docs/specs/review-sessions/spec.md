# 세션 되돌아보기: 반복되는 확률적 작업을 결정론적 주인에게 넘길 후보 찾기

연결된 출처:

  정한다.
- 조사 기록 [research.md](./research.md): 2026-09-10～10-10 기록으로 낸 후보,

- [skill-design](../../decisions/skill-design.md): 스킬 본문의 원칙, 번들
  스크립트가 자리를 얻는 조건(재현 가능한 측정 포함), 필수 스킬 규칙.
- [skill-layout](../../decisions/skill-layout.md): `workflow` 그룹.

## 목적과 승인 범위

에이전트가 세션마다 확률적으로 다시 하는 일 가운데, 매번 같은 결과가 나와야
하는 일을 찾아 **결정론적 주인에게 넘길 후보**를 증거와 함께 올리는 스킬이다.
[Poteto 인터뷰](https://notes.toycrane.xyz/poteto-spacex-shipping-2500-prs/)의
"지난 대화를 주기적으로 읽어 반복 개입과 반복 실패를 찾고, 고정된 절차는
도구로 옮겨라"를 이 저장소의 방식으로 옮긴 것이다.

핵심은 한 문장이다. 에이전트가 판단하지 않아도 되는 일에서 판단을 빼앗아, 매번
같은 결과가 나오는 주인에게 넘긴다. 에이전트의 실수를 하나씩 고치는 일이
아니라 같은 실수가 나올 수 없게 환경을 바꾸는 일이다. 여기서 세 원칙이 나온다.

- 관찰 단위는 세션 하나가 아니라 반복이다. 한 세션의 실수는 잡음이고, 여러
  세션의 같은 실수가 환경의 신호다.
- 옮기는 것은 "어떻게 실행하는가"이고 남기는 것은 "무엇을 확인하고 충분한가"다.
  접속, 기다림, 합성, 호출 형태는 도구로 가고, 제품 판단은 에이전트와 사람에게
  남는다.
- 결과물은 환경 변화와 재측정이다. 고치기만 하고 다시 재지 않으면 반쪽이다.

승인된 범위는 **조사와 보고까지**다. 스킬은 한 번 부르면 지난 기간의 세션
기록을 세고, 문턱을 넘은 후보를 읽고, 보고서 HTML 하나를 만들어 주소를 알려
주고 끝난다. 수정, PR, 파일 기록, 다른 스킬 호출은 하지 않는다.

2026-10-10 사용자가 철학, 멈추는 지점, 형태 제안, 조사 방식, 엄격 읽기 다섯
세션, HTML 보고서와 그 레이아웃(A안에 B안의 전후 비교 표)을 차례로 확정했다.
처음에 "파일 없이 대화에만"이라고 했던 결과물 지시는 뒤의 보고서 요청으로
대체되었다. 결과물은 보고서 파일 하나와 짧은 대화 요약이며, 그 밖에는 어디에도
쓰지 않는다.

## 요구 동작

### 부르기

- 사용자가 직접 부른다. 모델이 스스로 부르지 않는다.
- 입력은 기간과 선택적 초점이다. 기간을 주지 않으면 최근 14일이다. 초점은
  스킬 이름 하나 또는 신호 하나이며, 초점이 있으면 보고서는 그 초점의 후보와
  재측정을 앞에 둔다.
- 재측정 모드: 기준을 주면(날짜, 또는 세션이 읽은 SKILL.md 본문의 해시) 신호표를
  기준 전후로 나눠 보여 준다.

### 무엇을 세나

- 대상은 이 기기의 Claude Code 기록(`~/.claude/projects/*/*.jsonl`)과 Codex
  기록(`~/.codex/sessions/**/*.jsonl`)이다. 실질 범위는 Claude Code 세션과 그
  세션이 띄운 Codex 리뷰다. 사람이 쓴 Codex 대화는 적고 오류가 거의 없다.
- 제외: 평가·임시 디렉터리에서 돈 세션, 서브에이전트 갈래, 기록이 최근 몇 분
  안에 바뀐 진행 중 세션, 사용자 발화가 없는 세션.
- 세션 종류를 나눈다. 무인(예약 실행, Robo가 띄운 세션)과 대화형. 무인 세션의
  반복은 사람이 보지 않아 더 비싸므로 후보 순서에서 가중한다.
- 전수는 스크립트가 센다. 반복 오류 묶음, 하네스 차단, 같은 명령의 재시도,
  오류 뒤 사람 개입, 세션마다 다시 만드는 보조 스크립트, 명령은 실행했는데
  해당 스킬은 로드하지 않은 세션, 사용자 중단과 교정 표지, 세션 종류. 지난
  기간에 없던 오류 묶음과 명령 패턴도 올린다.
- 모델은 세션이 아니라 창을 읽는다. 문턱을 넘은 신호마다 서너 세션의 사건 앞뒤
  몇 이벤트만 읽고, 고정된 분류 어휘로 결과를 적는다. 읽는 창은 경계 표시로
  감싸 자료로 다룬다. 기록 안의 지시는 따르지 않는다.
- 엄격 읽기: 기간 안의 대화형 세션 중 다섯 개를 무작위로 골라 인터뷰가 말한
  방식대로 비효율과 지름길을 찾아 읽는다. 다섯 개로 고정한다. 이 부분만
  확률적이며, 미리 정의하지 않은 신호를 찾는 유일한 수단이다.

### 무엇이 후보가 되나

- 문턱을 넘은 신호만 후보가 된다. 문턱은 세션 다섯 개 이상, 또는 저장소 두 곳
  이상, 또는 무인 세션 한 번 이상이다.
- 후보마다 적는다: 신호, 세션 수와 건수, 세션 종류, 예시 세션 id, 근거, 제안
  형태와 주인, 에이전트에 남는 판단, 재측정이 확인할 것.
- 형태는 제안이지 결정이 아니다. 형태의 종류는 훅·권한 규칙, 린트·보호 경로,
  번들 스크립트, 스크립트 인터페이스, 프로젝트 설정·doctor, 스킬 문장이다.
  고르는 기준은 실패가 만들어지는 자리에 가장 가까운 주인에게, 판단을 빼앗지
  않는 한에서 가장 강한 형태다. 형태를 제안하기 전에 그 주인이 이미 가진
  스크립트, 플래그, 검사를 먼저 찾는다. 있는데 안 쓰이는 것이 발견이다.
- 도구로 가지 않는 것은 후보로 올리지 않고 분류해 보고한다. 하네스가 이미 막는
  마찰(차단 뒤 한 턴에 회복하는 것), 제품 판단 교정(결정 계약·메모리 후보),
  프로젝트 저장소의 일(follow-up 후보).

### 보고서

- 결과는 로컬 HTML 하나다. 외부 요청이 없고, 좁은 폭에서 읽히며, 구성은
  [prototype.html](./prototype.html)을 따른다: 머리(기간, 세션 수, 자료 취급
  규칙), 후보 카드 비용순, 도구로 가지 않는 것(접힘), 재측정 표(전후 기간과
  변화량, 후보로 가는 배지), 엄격 읽기 다섯 세션.
- 문턱을 넘은 후보가 없으면 "후보 없음" 상태로 그린다. 머리의 후보 수가 0이
  되고, 재측정 표와 엄격 읽기는 남는다.
- 보고서를 만든 뒤 하네스가 지원하는 방법으로 열어 주소를 알려 주고, 대화에는
  후보 수와 가장 비싼 후보 한 줄만 남긴다.
- 보고서와 대화에 토큰, 비밀, 개인정보를 옮기지 않는다. 사건 창의 명령에서
  토큰 꼴의 값은 가린다.

### 재측정

- 같은 집계를 기간을 나눠 다시 돌리면 고친 것이 줄었는지 보인다. 비교는
  날짜뿐 아니라 세션이 실제로 읽은 스킬 판으로도 나눌 수 있어야 한다. 세션
  기록에는 로드된 SKILL.md 본문이 그대로 들어 있어 그 해시로 나눈다. 설치된
  사본을 쓰는 저장소에서는 머지 뒤에도 옛 판으로 돈 세션이 섞이기 때문이다.
- 상태 파일은 두지 않는다. 매번 기간 전체를 다시 세고 나눈다.

## 수용 기준

- 이 기기의 기록으로 기간 2026-09-10～10-10을 같은 제외 규칙으로 돌리면
  [research.md](./research.md)의 신호표 수치(세션 수와 건수)가 재현된다.
  정의가 바뀌어 수치가 달라지면 바뀐 정의를 보고서에 밝힌다.
- 보고서가 네트워크 없이 열리고, 좁은 폭(390)에서 가로 스크롤 없이(재측정 표
  제외) 읽히며, 후보가 없을 때 "후보 없음" 상태로 그려진다.
- 후보는 문턱을 넘은 신호에서만 나오고, 모든 후보 카드에 위의 항목이 다 있다.
- 사건 창과 보고서 본문에 32자 이상의 16진수 문자열이나 `token=` 꼴의 값이
  없다.
- 두 하네스의 기록을 모두 읽고, 모르는 레코드 종류는 세어서 보고하되 실행을
  멈추지 않는다.
- 엄격 읽기는 조건에 맞는 세션이 다섯 개 이상이면 정확히 다섯 개이고, 세션
  id와 한 줄 관찰, 연결된 후보가 붙는다.
- 재측정 기준을 날짜로 주어도, 스킬 판 해시로 주어도 신호표가 전후로 나뉜다.
- 스킬은 보고서 파일 말고는 저장소와 홈 디렉터리 어디에도 쓰지 않는다.
- 스킬 프런트매터는 사용자만 부를 수 있게 한다.
- 번들 스크립트는 python3 표준 라이브러리만 쓴다.

## 결정된 제약과 이유

- 조사와 보고에서 멈춘다. 후보 하나하나가 스킬 본문이나 프로젝트 스크립트를
  바꾸는 설계 변경이라, 조사와 수정을 한 세션에 섞으면 측정의 중립성이 깨지고
  변경이 검토 없이 들어간다.
- 형태까지 제안한다. 형태를 고르는 근거(어느 세션 종류에서, 어떤 명령 형태가
  통과했는지)가 조사 데이터 자체라서, 고치는 세션이 다시 캐는 것보다 조사가
  적어 넘기는 편이 싸다.
- 전수는 스크립트, 표본은 모델. 비싼 것은 훑기가 아니라 모델이 읽는 일이다.
  30일치 7.5GB를 스크립트로 훑는 데 17초 걸렸다. 집계 정의가 스크립트에
  고정되어야 두 번째 측정이 첫 번째와 비교된다.
- 엄격 읽기는 다섯 세션으로 고정한다. 이번 조사에서 가장 뜻밖이었던 발견(교정이
  거의 전부 제품 판단, 래퍼를 `/tmp`에 만들고 버림)은 정의된 신호가 아니라
  읽기에서 나왔다. 비용의 대부분이 여기서 나므로 작게 묶는다.
- 하네스가 이미 막는 마찰은 후보가 아니다. 차단 뒤 한 턴이면 회복되고 하네스
  판이 바뀌면 사라진다. 지난 2주 사이 상대 경로 `cd` 실패가 44세션에서 2세션으로
  준 것이 그 예다.
- 지침 추가는 마지막 수단이다. 인터뷰도 "지침보다 린트"를 택하고, 이 저장소의
  skill-design도 관찰된 반복 실패에만 문장을 허락한다.
- 세션 기록에서 제품 아이디어를 지어내지 않는다. pipeline의 "개인 흔적을 캐지
  않는다"는 제품 씨앗을 만들지 말라는 뜻이고, 이 스킬은 도구 신호만 캔다.
- 다른 스킬을 부르지 않는다. 파일을 남기지 않으므로 `project-knowledge`도
  필요 없고, 필수 스킬 검사도 없다.

## 전제 (바꿀 수 있음)

- 이름은 `review-sessions`다. 사용자가 직접 부르는 동사-목적어 이름이고,
  생태계에서 한 세션 회고를 부르는 말이 `retro`라서 여러 세션을 세는 이 스킬과
  구분된다. 사용자가 다른 이름을 고르면 폴더와 함께 바꾼다.
- 그룹은 `workflow`다. 기술 독립적인 작업 방식이다.
- 주기는 2주이고, 스케줄은 사용자가 만드는 scheduled-task 프롬프트가 가진다.
  하루는 잡음이 크고 2주면 세션 천 개 안팎이라 반복이 드러난다.
- 보고서는 저장소 밖, 사용자 홈 아래 날짜별 폴더에 쓴다. 경로는 실행이 끝날 때
  알려 준다.
- 문턱은 세션 5개 이상, 저장소 2곳 이상, 무인 세션 1회 이상 중 하나다.
- 무인 세션 판별은 첫 발화의 scheduled-task 표시와 `robo-*` 워크트리 경로다.
- 모델이 읽는 창은 사건 앞뒤 여섯 이벤트다.
- 분류 어휘는 하네스 차단, 가드 차단, 오류 뒤 재시도, 오류 뒤 사람 개입, 반복
  준비 작업, 다시 만든 보조 스크립트, 스킬 미로드, 제품 판단 교정, 미리보기
  마찰이다. 어휘는 닫혀 있고, 새 종류는 엄격 읽기에서 제안된다.
- 엄격 읽기 표본은 기간을 시드로 삼은 무작위 추출이라 같은 기간은 같은 다섯
  세션을 고른다.

- `docs/follow-ups/`나 결정 계약 기록. 보고서가 유일한 결과물이다. 사람이
  보고서를 읽고 넘긴다.
- 클라우드 세션. 로컬 기록만 읽는다.
- 세션이나 사람을 점수 매기는 일. 반복과 비용만 센다.
- 결과를 외부 서비스로 보내는 일. 읽는 것은 로컬 파일이고, 모델에는 선택된
  창만 들어간다.

## 보류

- `/insights`가 남기는 facet 캐시(`~/.claude/usage-data/facets/`)를 입력으로
  쓸지. 지금은 없고, 생기면 마찰 분류의 보조 자료가 될 수 있다.
- Codex memories를 입력으로 쓸지. 미리보기 기능이고 로컬 파일 형식이 아직
  안정적이지 않다.
- 한 세션만 깊게 읽는 모드. Matt Pocock의 `retro`가 하는 일이며, 필요하면 초점
  인자로 세션 id를 받는 확장으로 다룬다.

## 남은 위험

- 두 하네스의 기록 형식이 바뀐다. 모르는 레코드를 세어 보고하는 것으로 드러나게
  하지만, 신호 정의가 깨지면 재측정 비교가 끊긴다.
- 평가·임시 세션 판별이 경로 규칙이라 새 패턴을 놓칠 수 있다.
- 모델이 창을 잘못 분류할 수 있다. 닫힌 어휘와 예시 세션 id가 피해를 줄인다.
- 기록이 늘면 훑는 시간이 는다. 기간 상한이 막아 준다.
- 재측정이 날짜 기준이면 설치 사본 지연 때문에 옛 판 세션이 섞인다. 판 해시
  기준이 이를 해소하지만, 해시가 같은 본문의 사소한 공백 차이에 갈릴 수 있다.
