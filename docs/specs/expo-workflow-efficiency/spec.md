# 리뷰 수정 뒤 최종 런타임 검증

## 목적과 승인 범위

`implement`가 구현 중 실제 동작을 확인하는 흐름은 유지하면서, 전체 변경의
최종 런타임 검증을 로컬 코드 리뷰와 필요한 수정 뒤에 수행한다. 리뷰에서 바뀔
수 있는 코드에 최종 검증을 먼저 수행하는 반복을 줄일 수 있는지 확인한다.

2026-09-15 사용자가 이 순서를 승인하고 명세 작성과 구현을 요청했다.
Expo에 한정하지 않고 `implement`가 다루는 제품 표면에 같은 순서를 적용한다.

## 요구 동작

1. 구현 중에는 의미 있는 동작 변경마다 관련 자동 검사와 가장 작은 실제 사용자
   흐름을 확인한다. 작업별 수용 기준과 승인 자료의 대조를 최종 검증 뒤로 미루지 않는다.
2. 모든 작업의 집중 검증과 대조가 끝나면 전체 결정적 자동 검사를 통과한 뒤
   전체 변경의 로컬 코드 리뷰를 한 번 수행한다. 리뷰에는 이미 얻은 집중 검증
   근거를 전달하며 최종 핵심 흐름 검증을 선행 조건으로 삼지 않는다.
3. 리뷰 지적 중 고쳐야 할 항목을 수정하고 영향을 받는 검증을 다시 수행한다.
4. 리뷰와 필요한 수정이 끝난 뒤, 전달할 버전에서 변경 흐름과 `PRODUCT.md`의
   대표 핵심 흐름을 검증한다. 결과에 포함하는 모든 플랫폼에서 직접 근거를 얻는다.
5. 최종 검증에서 문제가 나오면 수정하고 영향을 받는 검사와 최종 런타임 검증을
   다시 수행한다. 같은 로컬 리뷰 범위는 자동 재리뷰하지 않는다.
6. 사용자가 로컬 리뷰를 명시적으로 면제해도 최종 런타임 검증은 수행한다.
   리뷰가 차단되면 전체 완료를 보류하고 이미 확인한 결과와 정확한 차단 원인을 제공한다.
7. 이전 세션에서 최종 검증을 먼저 수행했더라도 이후 실행 동작이 바뀌었다면
   그 근거로 완료를 선언하지 않는다. 수정한 버전의 최종 검증이 필요하다.

## 수용 기준

- 수정이 없는 일반 경로에서 전체 자동 검사, 로컬 리뷰, 최종 런타임 검증 순서가 관찰된다.
- 리뷰 수정이 있는 경로에서 수정과 영향 검사가 끝나기 전에 최종 런타임 검증을 시작하지 않는다.
- 집중 검증은 리뷰 전에 유지되고, 최종 검증은 집중 검증만으로 대체되지 않는다.
- 최종 검증 실패 후 수정한 버전의 근거로만 완료하며 로컬 리뷰는 한 번으로 유지된다.
- 리뷰 면제 경로에서도 최종 검증을 거치며, 리뷰 차단이나 필수 런타임 검증 미완료를 완료로 보고하지 않는다.
- 기존 선행 검증 근거가 있는 재개 상황에서도 수정 뒤 검증을 생략하지 않는다.
- 핵심 흐름 부재, 승인 자료 대조, 플랫폼별 근거, 선언된 중간 리뷰 체크포인트와 PR 필수 리뷰의 기존 기준을 유지한다.
- 스킬 본문, 공개 설명과 결정 계약이 같은 순서를 설명하며 독립적인 행동 평가로 확인한다.
- 측정하지 않은 시간 절감률이나 실제 Expo 성능 개선을 완료 근거로 주장하지 않는다.

## 의존하는 결정

- [파이프라인](../../decisions/pipeline.md): 인계 자료, 검증과 리뷰, 완료 및 재개 기준을 정한다.
- [스킬 설계](../../decisions/skill-design.md): 독립 실행, 지침 범위와 관찰한 행동에 기반한 평가를 정한다.
- [문서 수명](../../decisions/document-lifecycles.md): 이 명세와 결정 계약의 수명을 정한다.

## 범위 밖

- worktree 준비, CLI 호환성 복구와 테스트 데이터 격리: 별도 개선이며 이번 승인 범위가 아니다.
- `expo-dev-loop`, `expo-smoke-test`의 검증 방법과 `merge`의 PR 필수 리뷰: 호출 순서 변경에 필요하지 않다.
- 리뷰 횟수 제한 완화, 미검증 플랫폼을 완료로 처리하거나 승인된 제품 기준을 축소하는 변경.
- 새 스킬, 영구 실행 원장, 별도 작업 분할 체계 추가.

## 가정과 남은 위험

시간 절감은 아직 검증하지 않은 가설이다. [세션 분석](research.md)은 조사 당시의
근거이며 이 명세 전체의 승인 범위를 넓히지 않는다. 최종 검증이나 PR 리뷰에서
새 문제가 나오면 재검증은 여전히 필요하다. 집중 검증 근거만 받은 리뷰가 중요한
결함을 더 늦게 발견하는지는 실제 사용에서 관찰한다.
