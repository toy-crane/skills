# 말투 추천과 글쓰기 피드백 재사용

## 사용자에게 달라지는 점

매체의 독자와 목적을 이야기하면 AI가 짧은 문단을 써서 말투를 추천한다.
사용자는 말투의 이름을 미리 정하지 않고 실제 문장을 읽고 반응한다.
사용자가 받아들인 예문과 특징은 다음 글에서도 참고할 수 있다.
글을 고칠 때 확인된 재사용 가능한 취향은 별도의 기억 요청 없이
기록한다. Claude와 Codex는 같은 저장소의 현재 기준을 읽고 다음 글의
기획과 초안에 적용한다.

## 확정한 범위

### 말투 추천

- `define-publication`은 알려진 독자와 목적을 바탕으로 짧은 추천 예문
  하나와 추천 이유를 먼저 보여준다. 사용자가 말투를 직접 설명하거나
  정해진 유형을 선택해야만 추천을 받을 수 있는 흐름을 만들지 않는다.
- 추상적인 표현은 예문의 특징을 설명하는 보조 수단으로 쓴다.
  "친근하면서 차분하게"라는 설명만으로 말투를 확정하지 않는다.
- 사용자가 문장을 고치거나 다른 느낌을 요청하면 그 반응에 맞춰 추천을
  조정한다. 비교가 필요할 때 대안을 추가한다.
- 추천과 채택을 구분한다. 사용자가 받아들이지 않은 문장을 매체의
  확정된 취향으로 저장하지 않는다.
- 채택한 예문과 사용자가 확인한 특징을 매체의 말투 기준에 남긴다.
  모든 매체가 공유하는 글쓴이의 문체는 기존 공통 문체 결정의 소유권을
  따른다. 같은 기준을 두 군데에 복제하지 않는다.
- 다음 글을 기획하고 쓸 때 해당 매체의 기준을 읽고 참고한다.
  예문의 내용이나 주장을 다른 글에 재사용하는 계약은 아니다.

### 수정에서 기준 남기기

- 사용자가 명확히 확인한 재사용 가능한 문체·구조 기준은 해당 수정에서
  기록하고 짧게 알린다. 같은 기준을 기록하기 위해 별도의 기억 요청이나
  반복 승인을 요구하지 않는다.
- 기존 원칙에 해당하면 그 원칙의 이유나 대표 예문을 보강한다.
  남기는 정보는 원칙, 수정 이유, 적용 범위, 비교에 도움이 되는 예문,
  사용자가 어떤 지시나 선택으로 확인했는지다. 모든 교정을 새 규칙으로
  늘리거나 추상적인 형용사와 금지 단어만 축적하지 않는다.
- 글의 주장과 범위는 해당 글의 계약에, 매체의 기본 말투는 매체 전제에,
  재사용할 문체·구조 기준은 해당 범위의 현재 결정에 둔다. 용어는 기존
  용어집을 따른다. 실제 수정 이력은 Git에 두고 같은 기준을 복제하지 않는다.
- AI가 새로 추론한 취향이나 적용 범위가 불명확한 일반화는 짧게 확인한다.
  단순 문장 교체, 반복 출현, 침묵만으로 전체 글의 영구적인 취향을 만들지
  않는다. 확정 전에는 후보로 표시하고 현재 규칙으로 저장하지 않는다.
- 뒤이은 수정으로 채택한 문장이 바뀌거나 삭제되면 그 예문의 채택 상태도
  갱신한다. 명시적인 일회성 예외는 그 글에만 적용하고, 기존 규칙을 바꾸는
  요청이면 현재 기준을 고친다.
- 이 보존 방식은 글 기획 중의 수정과 초안 이후의 사용자 교정에 적용한다.
  `project-knowledge`가 함께 설치되지 않아도 필요한 현재 기록을 남긴다.
  특정 도구의 개인 메모리에만 저장하지 않는다.

### 다음 글에서 기준 지키기

- 기획과 소제목, 초안에 관련 기준과 채택 예문을 적용한다. 재사용할
  기준점은 비교가 끝났다는 이유로 버리지 않는다. 개별 글의 비교 후보를
  모두 영구 보존하거나 브리프에 본문 초안을 넣지는 않는다.
- 표현을 쉽게 하거나 짧게 고칠 때 원래 주장과 주체를 보존한다. 새로운
  인과관계나 주장을 덧붙이는 방식으로 표현 문제를 해결하지 않는다.
- 사용자 지적이 낱말보다 주체, 역할, 중복, 연결의 문제라면 같은 원인이
  있는 제목과 본문, 그림을 함께 확인한다. 관련 없는 부분은 재작성하지 않는다.
- 초안을 넘기기 전에 확정된 문체·구조 기준과 예문에 대조한다. 독자 질문
  검증과 코드 실행 검증은 유지하되, 통과 사실을 문체 일치의 증거로 보지 않는다.
- 확정 기준 위반은 기존의 제한된 자동 수정 단계에서 고친다. 미확정 취향
  제안은 의견으로 구분하고, 무한한 교정이나 별도의 반복 검토를 만들지
  않는다. 사용자가 이후에 요청하는 수정은 자동 수정 횟수로 제한하지 않는다.
- 사용자 피드백이 해당 글의 주장을 바꾸면 기존 `define-piece`의 계약
  소유권을 따른다. 문체 학습이라는 이유로 AI가 새 주장을 확정하거나
  다른 글의 취향으로 저장하지 않는다.

## 관찰 가능한 수락 기준

1. 말투를 정하지 않은 사용자가 독자와 목적을 제공하면 AI가 실제 문단과
   짧은 추천 이유를 제시한다. 말투 용어를 먼저 고르도록 요구하지 않는다.
2. 사용자가 "너무 가르치는 느낌이야"라고 반응하면 설명용 형용사만
   바꾸지 않고 예문의 문장을 바꾼다.
3. 사용자가 다른 방향을 보고 싶어 하면 같은 내용을 유지한 비교 예문을
   제시한다. 비교를 위해 독자, 사실, 글의 주장을 임의로 바꾸지 않는다.
4. 사용자가 채택한 뒤 저장한 매체 기준에는 실제 예문과 확인된 특징이
   남는다. 나중에 대화 없이 그 기준을 읽어도 무엇을 추천하고 채택했는지
   확인할 수 있다.
5. 독자나 목적이 아직 불명확하면 매체 이름만으로 만들어내지 않는다.
   필요한 맥락을 확인하되 특정 독자 변화나 효용을 원하지 않는 개인 기록
   매체에도 적용할 수 있다.
6. 매체의 나머지 전제를 확인하고 저장하는 기존 절차를 유지한다.
   말투 추천을 했다는 이유로 글 본문 작성까지 진행하지 않는다.
7. 사용자가 적용 범위가 분명한 문체 원칙을 직접 지시하면 같은 수정에서
   해당 기록을 보강한다. 사용자가 별도로 "기억해"라고 할 때까지 기다리지
   않는다. 같은 원칙이 이미 있으면 중복 항목을 만들지 않는다.
8. 사용자가 소제목을 줄인 결과를 밋밋하다고 고치고 주장형 후보를 채택하면,
   기존 기준의 재사용 범위 안에서 "짧게"와 "주장을 드러낸다"를 함께
   보존한다. 특정 후보 선택만으로 모든 매체의 기본 문체를 변경하지 않는다.
9. 한 글에서 회사 예시를 바꾸거나 특정 문장을 강조한 요청은 별도의
   일반화 승인 없이 모든 글의 회사 목록이나 강조 규칙이 되지 않는다.
10. 수정 대화가 없는 새 세션이 기록만 읽고 다른 주제로 글을 쓸 때 관련
    기준을 적용한다. Claude가 기록하고 Codex가 읽는 경우와 그 반대
    경우에도 같은 현재 기준을 찾을 수 있다.
11. "쉽게 풀어줘"를 처리하면서 원래 없는 주장이나 인과관계를 만들지
    않는다. 주체 문제를 지적받으면 같은 역할을 설명하는 제목과 본문이
    서로 다른 주체를 가리키지 않는지 확인한다.
12. 독자 질문에는 답할 수 있지만 확정 문체 기준에 어긋나는 초안에서는
    해당 위반을 찾아 고친다. 미확정 선호를 새 규칙으로 만들거나 수정
    검토를 끝없이 반복하지 않는다.
13. 사용자에게 확인된 일회성 예외를 적용해도 다른 글의 기본 기준은
    유지된다. 기본 기준을 바꾸라는 명시적 요청에는 현재 문서를 갱신한다.
14. 글쓰기 스킬만 설치된 환경에서도 재사용할 기준이 공유 저장소에 남고,
    대화 속 완료 보고만으로 보존됐다고 주장하지 않는다.

## 제약과 이유

사용자는 "친근하면서 차분하게" 같은 표현만으로 AI가 어떤 글을 쓸지
예측하기 어렵다고 설명했다. 추천 문장을 먼저 읽게 하면 사용자에게
말투를 정의할 책임을 넘기지 않고도 선호를 확인할 수 있다.

말투 추천 권한은 독자와 목적을 대신 정할 권한이 아니다. 이미 확정된
매체 전제와 공통 문체를 우선한다.

조사한 두 도구의 작업 모두 사용자가 끝부분에서 별도로 요청한 뒤에
수정 원칙을 기록했다. Codex는 이미 존재한 글쓰기 결정을 읽고도 관련
수정 요청을 받았다. 기록 시점과 실제 적용을 함께 다뤄야 하며, 저장
위치만 늘리는 것으로 효과를 주장할 수 없다.

## 조정 가능한 가정

- 예문은 한 문단이면 충분한 것으로 시작한다. 문장 수나 고정 길이를
  요구하지 않고 차이를 판단할 수 있을 만큼만 쓴다.
- 예문의 배치와 설명 형식은 구현 과정에서 정하되, 예문이 설명보다
  먼저 판단 대상이 되도록 한다.
- 기록의 소제목과 예문 수, 기준 대조를 위한 구체적인 방법은 구현과
  평가에서 정한다. 사용자에게 별도 설정 항목을 고르도록 요구하지 않는다.
- 기존 글의 교정도 같은 피드백 보존을 적용하는 것으로 시작한다. 별도
  스킬을 추가하지 않고 기존 글쓰기 흐름을 활용하며, 브리프가 없는 경우
  해당 글과 명확한 수정 요청을 기준으로 범위를 제한한다. 없는 브리프나
  과거의 의도를 만들어내지 않는다.

## 이번 범위에서 제외하는 것

- 고정된 말투 목록이나 매체 종류별 자동 매핑.
- 이 스킬 개선 작업 자체에서 새 글을 발행하거나 기존 블로그 본문과
  블로그의 이미 승인된 취향을 바꾸는 것, 사이트 UI 제작.
- 공개 스킬에 특정 글쓴이의 취향을 기본값으로 넣는 것.
- 별도의 개인 기억 시스템이나 세션 전문을 매번 읽는 수정 일지.
- 사용자 승인 없는 주장 변경과 기존 문서 소유권의 변경.

## 남은 위험과 검증

현재 범위에서 구현 전에 추가로 정해야 할 사용자 선택은 없다.
예문 하나를 모든 상황에 그대로 적용하면 문체가 경직될 수 있으므로
채택한 특징과 적용 맥락을 함께 읽어야 한다. AI가 실제로 기준을 적용하는지와
한 글의 수정을 과도하게 일반화하지 않는지는 새 세션으로 검증해야 한다.

Claude와 Codex의 실제 수정 대화, 현재 기록 구조, 변경 후보와 평가
방법은 [research.md](research.md)에 있다. 같은 글 한 편을 조사한 결과라
개선 효과가 여러 주제에 전이되는지는 아직 확인하지 않았다. 현재 스킬과
수정한 스킬에 같은 자료를 주고 기록 시점, 재시작 후 적용, 주장 보존,
잘못된 일반화, 예외 처리를 비교한다. 개선에 사용한 문장만 다시 시험하지
않고 다른 주제와 표현에서도 확인한다. 연구 문서의 추가 후보는 이 계약에
명시된 범위만 채택하며, 다른 문서의 소유권까지 바꾸는 것으로 읽지 않는다.

## 구현과 남은 검증

세 글쓰기 스킬에 예문 추천·보존, 수정 시점의 피드백 기록, 다음 기획과
초안의 기준 대조를 반영했다. 단독 설치에서도 필요한 피드백 지침을
각 스킬 안에 포함했다. 기존 글의 제한된 교정과 자동 수정 이후의 사용자
교정도 같은 기준을 적용한다. 배포 버전은 `0.48.0`으로 준비했다.

플러그인·마켓플레이스 strict 검증, 두 에이전트의 스킬 심볼릭 링크,
평가 JSON과 fixture 경로, 참조 문서 연결, `git diff --check`는 통과했다.
행동 평가 20개와 합성 fixture를 준비했으며, 교차 도구 평가 순서는
[feedback-reuse.md](../../../skills/writing/draft-piece/evals/feedback-reuse.md)에
있다. 이 준비와 정적 검사는 행동 수락 기준의 통과 증거가 아니다.

실제 CLI 검증은 아직 완료하지 않았다. 격리 실행의 첫 Claude 호출은
로그인 정보에 접근하지 못해 모델 호출 전에 끝났다. 로그인·네트워크
접근을 위한 실행 요청은 자동 승인 검토가 외부 Claude 서비스에 스킬과
테스트 입력을 전송할 명시적 승인이 부족하다는 이유로 거절했다. 합성
테스트 자료와 변경 대상 SKILL.md만 Claude·Codex CLI로 보내는 범위의
승인을 요청했으며, 실제 블로그 글이나 세션 기록은 전송 대상이 아니다.
