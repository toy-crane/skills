# 실제 예문으로 매체의 말투 추천하기

## 사용자에게 달라지는 점

매체의 독자와 목적을 이야기하면 AI가 짧은 문단을 써서 말투를 추천한다.
사용자는 말투의 이름을 미리 정하지 않고 실제 문장을 읽고 반응한다.
사용자가 받아들인 예문과 특징은 다음 글에서도 참고할 수 있다.

## 확정한 범위

- `define-publication`은 알려진 독자와 목적을 바탕으로 짧은 추천 예문
  하나와 추천 이유를 먼저 보여준다. 사용자가 말투를 직접 설명하거나
  정해진 유형을 선택해야만 추천을 받을 수 있는 흐름을 만들지 않는다.
- 추상적인 표현은 예문의 특징을 설명하는 보조 수단으로 쓴다.
  "친근하면서 차분하게"라는 설명만으로 말투를 확정하지 않는다.
- 사용자가 문장을 고치거나 다른 느낌을 요청하면 그 반응에 맞춰 추천을
  조정한다. 비교가 필요할 때 대안을 추가한다.
- 추천과 채택을 구분한다. 사용자가 받아들이지 않은 문장을 매체의
  확정된 취향으로 저장하지 않는다.
- 채택한 예문과 사용자가 확인한 특징을 매체의 말투 기준에 남긴다.
  모든 매체가 공유하는 글쓴이의 문체는 기존 공통 문체 결정의 소유권을
  따른다. 같은 기준을 두 군데에 복제하지 않는다.
- 다음 글을 기획하고 쓸 때 해당 매체의 기준을 읽고 참고한다.
  예문의 내용이나 주장을 다른 글에 재사용하는 계약은 아니다.

## 관찰 가능한 수락 기준

1. 말투를 정하지 않은 사용자가 독자와 목적을 제공하면 AI가 실제 문단과
   짧은 추천 이유를 제시한다. 말투 용어를 먼저 고르도록 요구하지 않는다.
2. 사용자가 "너무 가르치는 느낌이야"라고 반응하면 설명용 형용사만
   바꾸지 않고 예문의 문장을 바꾼다.
3. 사용자가 다른 방향을 보고 싶어 하면 같은 내용을 유지한 비교 예문을
   제시한다. 비교를 위해 독자, 사실, 글의 주장을 임의로 바꾸지 않는다.
4. 사용자가 채택한 뒤 저장한 매체 기준에는 실제 예문과 확인된 특징이
   남는다. 나중에 대화 없이 그 기준을 읽어도 무엇을 추천하고 채택했는지
   확인할 수 있다.
5. 독자나 목적이 아직 불명확하면 매체 이름만으로 만들어내지 않는다.
   필요한 맥락을 확인하되 특정 독자 변화나 효용을 원하지 않는 개인 기록
   매체에도 적용할 수 있다.
6. 매체의 나머지 전제를 확인하고 저장하는 기존 절차를 유지한다.
   말투 추천을 했다는 이유로 글 본문 작성까지 진행하지 않는다.

## 제약과 이유

사용자는 "친근하면서 차분하게" 같은 표현만으로 AI가 어떤 글을 쓸지
예측하기 어렵다고 설명했다. 추천 문장을 먼저 읽게 하면 사용자에게
말투를 정의할 책임을 넘기지 않고도 선호를 확인할 수 있다.

말투 추천 권한은 독자와 목적을 대신 정할 권한이 아니다. 이미 확정된
매체 전제와 공통 문체를 우선한다.

## 조정 가능한 가정

- 예문은 한 문단이면 충분한 것으로 시작한다. 문장 수나 고정 길이를
  요구하지 않고 차이를 판단할 수 있을 만큼만 쓴다.
- 예문의 배치와 설명 형식은 구현 과정에서 정하되, 예문이 설명보다
  먼저 판단 대상이 되도록 한다.

## 이번 범위에서 제외하는 것

- 고정된 말투 목록이나 매체 종류별 자동 매핑.
- 새 글 작성, 기존 블로그 글 수정, 사이트 UI 제작.
- 공개 스킬에 특정 글쓴이의 취향을 기본값으로 넣는 것.

## 남은 논의와 위험

사용자는 실제 글을 고친 내용을 다음 글에 재사용하는 방식도 조사하도록
요청했다. 피드백의 보존 시점, 적용 범위, 다음 초안에서의 확인 방식은
별도 연구와 제안으로 정리하며, 이 문서의 확정된 말투 추천 계약과
구분한다. 예문 하나를 모든 상황에 그대로 적용하면 문체가 경직될 수
있으므로 채택한 특징과 적용 맥락을 함께 읽어야 한다.

Claude와 Codex의 실제 수정 대화, 현재 기록 구조, 변경 후보와 평가
방법은 [research.md](research.md)에 있다. 그 제안은 이 계약에 자동으로
포함되지 않는다.
